# v14 — train 내부 오류 분석과 제출 후보 검증

**결론: 제출 추천 후보 없음. 기존 v10을 유지하고 하루 한 번의 제출 기회를 진단용으로 쓰지 않습니다.** test/sample을 읽지 않았고 기존 홀드아웃의 예측·라벨로 점수를 계산하거나 후보를 선택하지 않았습니다. 이전 실행 메타데이터에서는 train 해시만 대조했습니다. 이 버전에는 새로운 홀드아웃 성능이나 Public 점수를 붙이지 않습니다.

## 오류에서 출발한 가설

개발 OOF에서 GBMLGG→LGG 153건, KIPAN→KIRC 140건, BRCA→OV 77건 등 쌍별 혼동이 컸습니다. THYM/PRAD/PCPG의 낮은 정밀도는 불균형 보정의 과도한 영향 가능성을, KIPAN의 낮은 재현율은 관련 클래스 간 조건부 구분의 어려움을 시사합니다. 이것은 관찰에 근거한 가설이지 임상 원인 확정이 아닙니다.

## 분리·재현·보관

1차와 기존 재분할 모두 원본/정규화 프로필이 학습·검증 사이에 겹치지 않음을 확인했습니다. ID는 모델 입력에서 제외했고 test/sample open을 audit hook으로 차단했습니다. 기존 홀드아웃은 점수 계산에 사용하지 않았습니다. 과거 버전에서 test 분포와 홀드아웃을 관측했던 설계 편향은 사라지지 않습니다. 기준을 통과한 후보가 없어 전체 train 최종 모델이나 제출 CSV를 새로 만들지 않았습니다. 실험용 쌍 분류기의 학습·선별·검증은 이 노트북 안에서 수행합니다. 검증된 캐시가 없으면 baseline도 재학습하므로 별도 프로젝트 .py 파일은 필요하지 않습니다.

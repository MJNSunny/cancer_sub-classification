# 혜진의 암 분류 AI 이야기: 처음 제출부터 v6 실험까지

> 중학생도 이해할 수 있게 정리한 개발·제출 기록입니다.
>
> **작성 기준: 2026년 11월 9일.** 혜진님이 대화에서 알려준 대회 점수와 저장된 실험 기록을 기준으로 작성했습니다. 확인된 대회 점수는 v1·v3·v4의 세 개입니다. v2는 별도 실험 기록입니다. v4 Public **0.3169555443**은 혜진님이 공유한 실제 제출 결과를 반영했습니다.

## 먼저, 어떤 문제를 풀고 있나요?

이 대회는 **“환자의 유전자 변이 단서를 보고, 26개 암종 중 하나를 고르는 탐정 시험”**입니다.

- **공부할 문제집 `train.csv`:** 정답이 있는 환자 6,201명의 데이터입니다.
- **실전 시험지 `test.csv`:** 정답이 제공되지 않은 환자 2,546명의 데이터입니다.
- **살펴볼 원본 유전자:** 실제 파일에는 4,384개 유전자 컬럼이 있습니다.
- **`WT`:** 해당 칸이 변이 없음으로 표기되어 있다는 뜻입니다.
- **변이 문자열:** `R132H`, `R213*`처럼 유전자에서 관측된 차이를 적은 단서입니다. 변이가 있다고 모두 암의 원인이라는 뜻은 아닙니다.

우리는 환자별 단서를 숫자로 바꾸고, 정답이 있는 문제집으로 규칙을 학습한 뒤, 실전 시험지의 답을 제출합니다.

### 점수 이름부터 구분해 봅시다

| 이름 | 쉬운 뜻 | 알아둘 점 |
| --- | --- | --- |
| 개발 CV F1 | 공부용 문제를 3묶음으로 나눠 돌아가며 보는 모의고사 평균 | 모델과 설정을 고르는 데 사용했습니다. |
| 홀드아웃 F1 | 따로 떼어 놓은 1,241명의 정답으로 채점한 결과 | 여러 실험에서 이미 확인한 데이터여서 완전히 새로운 시험은 아닙니다. |
| Public 점수 | 대회 사이트에 답안지를 제출하고 받은 점수 | 로컬 점수가 높아도 똑같이 나오지는 않습니다. |
| 정확도 | 전체 환자 중 암종을 맞힌 비율 | F1과 다른 지표입니다. |

**Macro F1은 26개 암종의 F1을 같은 비중으로 평균한 점수입니다.** 많이 등장하는 암종뿐 아니라 적게 등장하는 암종도 잘 분류해야 합니다. F1이 `0.4445`라고 해서 환자의 `44.45%`를 맞혔다는 뜻은 아닙니다. v4의 실제 홀드아웃 정확도는 **43.76%**입니다.

## 1. v1: 단서를 많이 모으고, 두 탐정의 의견을 합쳤습니다

> “유전자에 변이가 있는지만 볼까? 어떤 종류인지, 어느 위치인지도 함께 보자!”

### 어떤 단서를 만들었나요?

원본 유전자 컬럼은 4,384개지만, 한 컬럼에서 여러 종류의 단서를 만들 수 있습니다.

예를 들어 `IDH1` 유전자에 `R132H`라는 값이 있다면 다음과 같이 나눠 봅니다.

- `IDH1`에 변이가 있다.
- 정확한 변이 표기는 `R132H`다.
- 숫자 위치는 `132`다.
- 표기상 아미노산 치환에 해당한다.

이렇게 만든 단서 중 학습 데이터에서 반복해서 등장한 것을 남겼습니다.

| 단서 종류 | 최종 개수 | 쉬운 설명 |
| --- | ---: | --- |
| 유전자별 변이 유무 | 4,215 | 이 유전자에 변이가 있는가? |
| 정확한 변이 표기 | 2,254 | 같은 유전자에서 정확히 이 변이가 나타났는가? |
| 변이의 숫자 위치 | 4,171 | 이 위치에 변이가 있는가? |
| 유전자별 변이 유형 | 10,783 | 치환·동의적 변이·종결·프레임시프트 등 어떤 표기인가? |
| 환자 전체 요약 | 18 | 변이 유전자 수, 유형별 개수·비율 등은 어떠한가? |
| 유전자 그룹 요약 | 7 | 수작업으로 묶은 유전자 그룹에 변이가 몇 개 있는가? |
| **합계** | **21,448** | 원본 유전자 수와 파생변수 수는 다릅니다. |

범주형 단서는 해당 학습 부분에서 3명 이상에게 관측된 것을 남겼습니다. 개수 요약에는 주로 `log(1 + 개수)`를 사용해 큰 값의 영향을 완화했습니다. **v1은 모든 환자의 단서 벡터를 같은 크기로 맞추는 행 정규화 모델이 아니었습니다.**

### 두 탐정은 어떻게 협력했나요?

1. **로지스틱 회귀:** 단서마다 배운 가중치를 적용해 암종별 점수를 계산합니다.
2. **ExtraTrees:** 여러 결정트리의 질문과 판단을 합칩니다.

두 모델이 낸 암종별 예측 확률을 **절반씩 평균**해 최종 답을 골랐습니다.

### 결과와 배운 점

- 홀드아웃 F1: **0.4237**
- 홀드아웃 정확도: **42.79%**
- 실제 Public 점수: **0.2765425197**

모의고사와 실전의 차이가 컸습니다. **학습·검증·테스트를 분리했다는 사실만으로 실전 성능까지 보장되지는 않는다는 것**을 확인했습니다.

실제 제출 파일은 저장된 예측 파일과 같았고, ID 정렬 오류는 발견하지 못했습니다. 이어서 데이터의 단서 표기와 분포 차이를 살펴봤습니다.

## 2. v2 실험: 다른 방법도 시도했지만, 성적표를 보고 채택하지 않았습니다

> “모델을 바꾸거나 단서를 정리하면 나아질까? 직접 비교해 보자!”

### 데이터에서 확인한 차이

| 관찰 항목 | 학습 데이터 | 테스트 데이터 |
| --- | ---: | ---: |
| 환자당 변이 유전자 수 중앙값 | 14개 | 28개 |
| 환자당 변이 유전자 수 평균 | 약 35.3개 | 약 78.1개 |
| 한 칸에 여러 변이가 적힌 비율 | 약 10% | 약 32% |
| 결측 칸 | 0개 | 237개 |

테스트에는 단서가 더 많이 적힌 환자와, 한 유전자 칸에 여러 표기가 들어 있는 사례가 더 많았습니다.

이 차이는 **주석 방식이나 데이터 구성 차이의 가능성**을 보여줍니다. 이것만으로 “일반인의 유전자가 섞였다”, “특정 암 환자가 정확히 몇 명이다”라고 확정할 수는 없습니다.

### 무엇을 비교했나요?

- 유전자 변이 유무만 사용하는 방법
- 유전자별 변이 유형을 사용하는 방법
- 정확한 변이·위치를 정규화해 사용하는 방법
- TF-IDF로 흔한 단서와 드문 단서의 비중을 바꾸고, 환자별 벡터 크기를 정규화하는 방법
- 로지스틱 회귀, LightGBM, ExtraTrees
- 학습 데이터 안에서 합성 배경 변이를 추가하는 방법
- 로지스틱 회귀의 규제 강도를 바꾸는 방법

단일 설정 14개와 앙상블 후보를 비교했습니다. 배경 변이가 섞였을 때 점수가 얼마나 변하는지도 함께 확인했습니다. 최종 실험 후보는 다음 결과를 냈습니다.

- 개발 CV의 깨끗한 데이터 F1: **0.3810**
- 홀드아웃 F1: **0.3758**

기존 홀드아웃 F1 `0.4237`을 넘지 못해 이 후보를 기본 모델로 교체하지 않았습니다.

**배운 점:** 새로운 기법을 넣었다는 사실과 성능이 좋아졌다는 사실은 다릅니다. 시도한 방법과 최종 채택한 방법을 구분해야 합니다.

## 3. v3: 같은 뜻의 단서인데 표기가 달랐습니다

> “문제집에는 별표로 적혔는데, 시험지에는 X로 적혔다면?”

### 어떤 차이를 수정했나요?

종결 변이로 다루는 표기에서 학습에는 `*`가 쓰였고, 테스트에는 `X`가 많이 나타났습니다.

```text
학습에서 보던 표기: R213*
테스트의 다른 표기: R213X

v3의 통일 규칙: R213X → R213*
```

이 규칙은 **아미노산 문자와 숫자 위치 뒤에 오는 종결 `X`**에 적용했습니다. 데이터 안의 모든 문자 X를 무작정 바꾼 것이 아닙니다.

### 모델을 다시 바꾼 건가요?

이 단계에서는 기존 로지스틱 회귀 + ExtraTrees의 학습 가중치를 유지하고, 전처리의 표기 해석을 수정했습니다.

학습 6,201명 전체에 대해 수정 전후의 특성 행렬을 비교했습니다. 두 모델 모두 **달라진 항목이 0개**였습니다. 학습에서는 원래 쓰던 표기를 그대로 해석하면서, 테스트의 다른 표기를 학습에서 배운 단서와 연결한 것입니다.

### 결과는 어땠나요?

- 기존 제출 대비 **348개 예측 라벨**이 달라졌습니다.
- 홀드아웃 F1은 **0.4237로 동일**했습니다.
- 실제 Public 점수는 **0.2765425197 → 0.2998780222**로 올랐습니다.
- 상승 폭은 **약 0.02334점**입니다.

348개가 달라졌다는 것은 **348개를 추가로 맞혔다는 뜻이 아닙니다.** 테스트 정답이 없으므로 개별 변경이 맞았는지는 알 수 없습니다. 대회가 돌려준 점수로 전체적인 상승을 확인한 것입니다.

**배운 점:** 모델을 더 복잡하게 만들기 전에, 학습과 추론에서 같은 의미의 입력을 같은 방식으로 해석하는지 확인할 가치가 있습니다. 표기를 맞췄어도 변이량·주석 범위 차이까지 모두 해결된 것은 아닙니다.

## 4. v4: “단서가 너무 많아서 헷갈리는 것 아닐까?”를 실험했습니다

> “같은 말을 반복하는 단서는 줄이고, 암종과 관련 있는 단서를 골라 보자!”

혜진님이 제안한 출발점은 다음과 같았습니다.

> “변수를 모조리 다 쓰니까 성능이 떨어진 것일지도 몰라. 연관관계가 높은 것들을 골라서 다시 해 보자.”

여기서 두 단어를 구분했습니다.

- **입력 변수:** 탐정이 보는 단서입니다. 예를 들어 `IDH1`의 변이 유무가 한 변수입니다.
- **하이퍼파라미터:** 학습 방법을 정하는 조절 손잡이입니다. 몇 개의 변수를 남길지, 얼마나 강하게 규제할지 등이 여기에 해당합니다.

### ① 암종과 관련 있는 단서를 먼저 골랐습니다

세 가지 선별 방식을 비교했습니다.

| 방법 | 쉬운 비유 |
| --- | --- |
| 카이제곱(chi2) | “이 단서가 어떤 암종에서 유독 자주 보이나?”를 살핍니다. |
| ANOVA F | “암종마다 이 단서 값이 얼마나 다르게 나타나나?”를 살핍니다. |
| L1 로지스틱 기반 선별 | 여러 단서를 함께 보면서, 규제를 통해 일부 단서의 가중치를 0으로 만들고 남은 것을 살핍니다. |

암종은 이름표 같은 범주입니다. 암종에 임의의 숫자를 붙여 그 숫자와 단서의 단순 상관을 구하는 방식은 사용하지 않았습니다.

### ② 거의 같은 말을 하는 단서의 중복을 줄였습니다

어떤 데이터에서는 “이 유전자에 변이가 있음”과 “이 유전자에 치환 표기가 있음”이 거의 항상 함께 나타날 수 있습니다.

이런 **입력 변수끼리의 중복**은 Pearson 상관으로 살폈습니다. 절대 상관이 0.95 또는 0.99 이상이면, 타깃 연관성 순위가 높은 쪽을 대표로 남기는 방법을 비교했습니다. 최종 선택 모델들은 **0.95 기준**을 사용했습니다.

같은 유전자에 관한 단서라고 모두 지운 것은 아닙니다. 서로 다른 정보를 주면 함께 남을 수 있습니다. 상관이 높다는 것이 생물학적으로 완전히 같은 뜻이라는 의미도 아닙니다.

### ③ “얼마나 줄일까?”도 시험했습니다

처음에는 64·128·256·512개를 비교했습니다. 너무 적게 남기면 필요한 단서까지 잃어 점수가 떨어지는 경향을 확인했습니다.

그래서 **1,024·2,048개** 구간까지 확장했습니다. 환자 전체 요약값을 제외하는 버전과 유지하는 대조군, 로지스틱 회귀의 규제 강도, 트리의 잎 수·깊이도 비교했습니다.

초기 80개에 추가 61개를 더해 **총 141개 단일 설정을 같은 그룹 3-fold에서 평가**했습니다. 학습 중 생성한 암종별 서명 점수 26개를 쓰는 방식도 포함했지만, 최종 앙상블에는 선택되지 않았습니다.

### ④ 최종적으로 어떤 세 모델을 골랐나요?

| 모델 | 직접 받는 선택 변수 | 주요 설정 |
| --- | ---: | --- |
| **로지스틱 회귀** | 2,048개 | 카이제곱 선별, 중복 상관 기준 0.95, 규제 `C=0.1` |
| **LightGBM** | 2,048개 | ANOVA F 선별, 환자 요약 유지, 중복 상관 기준 0.95, 잎 수 15 |
| **ExtraTrees** | 1,024개 | ANOVA F 선별, 환자 요약 유지, 중복 상관 기준 0.95, 최대 깊이 20 |

세 모델은 **각자 선택된 변이 특성을 직접 학습**합니다. 최종 답은 세 모델의 암종별 확률을 **같은 비중으로 평균**해 고릅니다.

같은 단서를 여러 모델이 함께 쓰기도 합니다. 따라서 `2,048 + 2,048 + 1,024 = 5,120`은 모델별 입력 칸을 모두 더한 수이고, **중복을 한 번만 세면 실제 선택 변수 합집합은 2,063개**입니다.

이는 **유전자 2,063개를 쓴다는 뜻이 아닙니다.** 유전자 유무·변이 유형·정확한 변이·위치·요약값을 포함한 파생변수의 수입니다. 선택되지 않은 원본 유전자도 환자 전체 요약값 계산에는 영향을 줄 수 있습니다.

### ⑤ 얼마나 달라졌나요?

| 비교 항목 | v3 | v4 |
| --- | ---: | ---: |
| 선택 파생변수 합집합 | 21,448개 | **2,063개** |
| 모델 파일 크기 | 약 344MiB | **약 40MiB** |
| 기존 홀드아웃 Macro F1 | 0.4237 | **0.4445** |
| 기존 홀드아웃 정확도 | 42.79% | **43.76%** |
| 개발 CV Macro F1 | **0.4183** | 0.4132 |

변수 합집합은 **약 90.4% 감소**했습니다. 홀드아웃 F1은 **약 0.02084점 상승**했습니다.

실제 제출에서도 Public이 **0.2998780222 → 0.3169555443**으로 **0.0170775221점 상승**했습니다. 최초 제출의 0.2765425197과 비교하면 **0.0404130246점 상승**입니다. 다만 변수 선별·규제·모델 구성이 함께 바뀌었으므로, 이 상승을 변수 개수 감소 하나만의 효과로 단정할 수는 없습니다.

다만 **개발 CV는 약 0.00510점 낮아졌습니다.** 가중 스트레스 점수도 v3 `0.3451`, v4 `0.3422`로 소폭 낮았습니다. 그래서 “어디서나 더 잘 맞히는 모델이 완성됐다”고 말할 수는 없습니다. v4는 입력 축소라는 실험 목적에 맞춰 축소 후보 안에서 선택한 모델입니다.

### 실제로 좋아진 홀드아웃 사례도 있었나요?

`THYM` 암종에서 변화가 있었습니다.

- 홀드아웃에는 실제 `THYM` 샘플이 **30명** 있었습니다.
- v3는 이 30명을 맞히지 못해 해당 클래스 F1이 **0**이었습니다.
- v4는 30명을 모두 찾아 해당 클래스 F1이 **약 0.4196**이 됐습니다.
- 하지만 v4가 `THYM`이라고 예측한 사람은 **113명**이었습니다. 이 중 30명만 맞았으므로 잘못 지목한 사례도 많았습니다.

**놓치는 문제를 줄였어도, 다른 암종을 잘못 끌어오는 문제는 남아 있습니다.** 이것은 정답을 알고 있는 홀드아웃 사례이며, 테스트 환자에게 같은 결과가 난다는 뜻은 아닙니다.

## 6. 공부용 문제와 실전 시험지는 어떻게 분리했나요?

```text
정답이 있는 train 6,201명
├── 개발 데이터 4,960명
│   └── 그룹 3-fold로 변수 선택·하이퍼파라미터 비교
└── 홀드아웃 1,241명
    └── 선택한 설정을 재평가

선택한 설정 → train 전체 6,201명으로 최종 학습
            → test 2,546명은 예측만 수행
            → 새 submission CSV 저장
```

- 완전히 같은 원본 변이 프로파일은 같은 그룹으로 묶어, 개발·검증 양쪽에 흩어지지 않도록 했습니다.
- 단어 사전, 빈도 필터, 타깃 연관성, 상관, 스케일링 등은 해당 학습 부분에서 적합했습니다.
- 테스트는 EDA에서 표기·결측·분포를 확인하고 최종 예측하는 데 사용했습니다. 학습 행에 합치거나 변수 선별·모델 가중치 적합에 사용하지 않았습니다.
- 테스트 정답은 제공되지 않았고, 정답을 복사해 예측하지 않았습니다.

단, **홀드아웃 점수는 여러 번 확인했습니다.** 개발 CV도 많은 후보를 고르는 데 반복 사용했습니다. 따라서 로컬 최고 점수에는 선택 편향이 있을 수 있고, 새 데이터의 성능은 별도로 확인해야 합니다.

### 배경 변이 스트레스 검증은 무엇인가요?

탐정에게 원래 단서와 함께 추가 단서를 섞어 주고 얼마나 흔들리는지 살펴보는 시험입니다.

v4에서는 검증 행에 학습 부분의 유전자 빈도를 이용한 합성 배경 변이를 평균 10개 또는 40개 추가했습니다. 후보 선택은 다음 점수를 사용했습니다.

```text
선택 점수 = 깨끗한 검증 F1 × 0.5
          + 배경 10개 검증 F1 × 0.25
          + 배경 40개 검증 F1 × 0.25
```

이것은 **모델의 민감도를 비교하기 위한 합성 시험**입니다. 실제 테스트의 변이 분포나 생물학적 변이를 재현한 것이 아니며, 이 점수를 Public 점수로 읽으면 안 됩니다.

## 7. 혜진의 실험에서 배운 것

### 배운 점 1. 모의고사와 실전 점수는 따로 기록해야 합니다

v1의 홀드아웃 F1은 `0.4237`이었지만 Public은 `0.2765`였습니다. 로컬 점수만 보고 실전 결과를 미리 확정하면 안 됩니다.

### 배운 점 2. 같은 뜻의 입력을 다르게 읽는 문제부터 확인해야 합니다

v3는 학습 가중치를 그대로 유지한 표기 수정으로 Public이 약 `0.02334` 올랐습니다. 복잡한 모델 추가뿐 아니라 입력 정합성도 점검할 가치가 있습니다.

### 배운 점 3. 변수는 많아도 문제이고, 너무 적어도 문제일 수 있습니다

64개나 128개로 줄였을 때는 필요한 정보를 잃는 경향이 있었습니다. 관련 단서를 골라 중복을 줄이고 **남길 개수도 검증으로 정해야 합니다.** “변수를 줄이면 무조건 점수가 오른다”는 결론은 아닙니다.

### 배운 점 4. 시도한 방법과 채택한 방법을 구분해야 합니다

TF-IDF, 배경 변이 증강, 암종별 서명, L1 선별도 시험했습니다. 그러나 **v4의 최종 구성은 카이제곱·ANOVA F 선별과 상관 중복 제거를 거친 로지스틱·LightGBM·ExtraTrees 앙상블**입니다. 모든 실험 기법이 최종 모델에 들어간 것은 아닙니다.

### 배운 점 5. “무엇이 개선됐는지”를 정확히 표현해야 합니다

v4는 변수 수·파일 크기·기존 홀드아웃 결과가 개선됐고, 실제 Public도 **0.2998780222 → 0.3169555443**으로 올랐습니다. 반면 개발 CV는 소폭 낮아졌습니다. 이 사례에서 제출 점수 상승은 확인했지만, 변수 축소가 언제나 효과가 있다는 뜻은 아닙니다. 로컬 홀드아웃 0.4445와 Public 약 0.3170 사이의 차이도 여전히 남아 있습니다.

## v5 추가 실험: 아미노산 변화와 희귀 배경 변이에 덜 흔들리는 모델

v5의 실제 대회 점수는 아직 공유되지 않았습니다. 현재 확인된 최고 Public은 v4의 **0.3169555443**입니다.

### 무엇을 바꿨나요?
- 원래 44개 후보에 규제·지원도 12개와 희귀 변이 증강 3개를 추가해 **59개 설정**을 비교했습니다.
- 유전자별 아미노산 변화(예: `R>H`)를 보완 단서로 추가했습니다. 다른 위치의 효과가 같다는 의미는 아닙니다.
- 일부 표현은 학습에서 반복 관측된 변이에 더 무게를 주고, 낯선 치환·동의적 변이는 낮은 가중치로 비교했습니다. 유해/무해함을 확정한 규칙은 아닙니다.
- 토큰 개수 대신 유전자별 요약을 사용하고 같은 토큰을 중복 제거했습니다. 최종 앙상블에 기존 v4가 일부 섞여 전체 예측의 완전한 중복 불변성을 보장하지는 않습니다.
- 새 LightGBM과 XGBoost는 학습에서 관측된 희귀 변이를 붙인 합성 복사본도 학습했습니다. 복사본은 원래 라벨을 유지한다는 가정이므로 실제 생물학과 다를 수 있습니다. 사전·선별은 원본 학습에서만 적합했습니다.

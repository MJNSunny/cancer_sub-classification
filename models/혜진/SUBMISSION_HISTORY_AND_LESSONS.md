# 혜진 암종 분류 모델 개선 및 버전별 실험 기록

> 작성 기준: 2026년 11월 9일. 대화에서 혜진님이 알려준 실제 대회 점수와 저장된 설정·CV·검증 결과를 대조해 정리했습니다. 버전 번호는 실험 순서이며, 모든 버전이 주 모델로 채택되거나 대회에 제출된 것은 아닙니다. 개별 버전의 제출 날짜는 확인하지 못했으므로 임의로 붙이지 않았습니다.

## 1. 현재 상태와 이 문서를 읽는 방법

- **현재 주 모델은 v6입니다.** `cencer.ipynb`, `analysis_report.md`, `gene_dictionary.md`는 v6를 유지합니다.
- **사용자가 알려준 Public 점수 중 최고는 v4의 0.3169555443입니다.** v5·v6의 Public 점수는 아직 공유되지 않았습니다. v6가 실제 대회에서도 최고라는 뜻은 아닙니다.
- **v7은 신규 후보를 채택하지 않았습니다.** 1차 CV 향상이 재분할에서 유지되지 않았습니다.
- **v8도 주 모델을 교체하지 않았습니다.** 다만 개발 CV에서 작은 개선이 있었던 뇌·신장 쌍별 보정 모델을 `v8_experimental`로 따로 저장했습니다. 안정적 개선이나 Public 향상을 확인한 모델은 아닙니다.
- **실제 제출이 확인된 버전은 v1·v3·v4입니다.** CSV 생성, 모델 채택, 대회 제출, Public 확인은 서로 다른 상태로 기록합니다.

이 문서는 각 버전의 **문제의식 → 전처리·파생변수 → 비교한 학습 설정 → 최종 구성 → 검증 결과 → 채택 판단 → 배운 점** 순서로 정리합니다. 실패한 후보도 이후 판단의 근거이므로 함께 남깁니다.

### 1.1 지표를 혼동하지 않기

| 용어 | 의미 | 해석 시 주의점 |
| --- | --- | --- |
| 개발 CV Macro F1 | 개발 환자를 그룹 3-fold로 나누어 계산한 F1의 평균 | 모델·변수·가중치를 고르는 데 반복 사용함 |
| 재분할 CV | 같은 개발 환자를 다른 seed로 나눈 그룹 3-fold | 분할 민감도 점검이며 새로운 독립 환자가 아님 |
| 홀드아웃 | 개발에서 제외한 1,241명에 대한 평가 | 여러 버전에서 이미 확인했으므로 최종 독립 시험이 아님 |
| 정확도 | 전체 환자 중 정답을 맞힌 비율 | Macro F1과 다른 지표 |
| Macro F1 | 26개 암종의 F1을 같은 비중으로 평균 | 환자가 적은 암종도 같은 비중을 가짐 |
| Weighted F1 | 암종별 환자 수로 가중한 F1 | Macro F1을 대신하는 수치가 아님 |
| 스트레스 F1 | 인위적으로 추가 변이나 중복 표기를 넣은 검증의 F1 | 실제 test 분포나 Public 점수와 같지 않음 |
| 종합 선택 점수 | 여러 검증 조건의 F1을 정해진 비율로 평균 | 대회 제출 점수가 아님 |
| Public | 제출 후 대회 사이트가 알려준 점수 | 사용자가 알려준 값만 실제 결과로 기록함 |

예를 들어 v6의 Macro F1 `0.472989`는 정답률 47.30%라는 뜻이 아닙니다. v6의 같은 홀드아웃 정확도는 **46.33%**입니다. 아래 표의 소수는 반올림했으며, 상세 기록에는 더 긴 원래 값이 저장돼 있습니다.

## 3. 데이터에서 출발한 문제의식

### 3.1 컬럼과 기본 규모

| 항목 | 내용 |
| --- | --- |
| train | 환자 6,201명, 정답 `SUBCLASS` 26개 |
| test | 환자 2,546명, 정답 제공 안 됨 |
| 원본 유전자 컬럼 | 실제 CSV 기준 4,384개 |
| `ID` | 샘플 식별용, 예측 입력에서 제외 |
| `SUBCLASS` | 학습 정답, 입력 변수에서 제외 |
| `WT` | 해당 칸에 변이 없음으로 기록됨 |
| 변이 문자열 | `R132H`, `R213*`, `K16fs` 등, 공백으로 여러 토큰이 함께 기록되기도 함 |

원본 유전자 수와 파생변수 수는 다릅니다. 한 유전자에서 존재 여부·위치·변이 종류·정확한 표기 등 여러 변수를 만들 수 있습니다. 변이가 기록됐다는 사실은 그 변이가 암의 원인이라는 증명이 아닙니다.

### 3.2 train/test에서 실제로 관찰한 차이

| 항목 | train | test |
| --- | ---: | ---: |
| 변이가 기록된 유전자 칸 수 | 218,893 | 198,930 |
| 공백으로 나눈 원시 변이 토큰 수 | 255,164 | 337,512 |
| 환자당 변이 유전자 수 평균 | 약 35.3 | 약 78.1 |
| 환자당 변이 유전자 수 중앙값 | 14 | 28 |
| 여러 토큰이 들어 있는 변이 칸 | 22,026 | 63,178 |
| 변이 칸 중 다중 토큰 칸의 비율 | 약 10.1% | 약 31.8% |
| 결측 칸 | 0 | 237 |
| 종결 표기로 다룬 `X` 토큰 | 0 | 14,477 |

다중 토큰 비율의 분모는 전체 유전자 칸이 아니라 **변이가 기록된 칸**입니다. 원시 토큰 수는 중복 제거 전 개수입니다.

이 차이는 표기·주석 범위·코호트 구성 등의 차이 가능성을 보여줍니다. 이것만으로 test에 일반인 유전자가 섞였다고 확정하거나 특정 암종 환자 수를 알아냈다고 말하지 않았습니다. 변이 유전자 수는 mutations/Mb 단위의 임상 TMB도 아닙니다.

### 3.3 같은 입력인데 정답이 다른 사례

v7 점검에서 완전히 같은 원본 변이 프로필은 5,636개였고, 그중 **447개 프로필 그룹·1,005개 행**에 서로 다른 암종 정답이 붙어 있었습니다. ID를 쓰지 않는 결정적 분류기는 완전히 같은 입력을 서로 다른 정답으로 모두 맞힐 수 없습니다.

원본 프로필별 최빈 정답을 고른다고 가정해도 학습 데이터에서 최소 511개 오류가 남는다는 기술통계를 얻었습니다. 이에 따른 약 91.76%는 **원본 학습 데이터에서의 정확도 상한 계산**이지, test 성능·Macro F1 상한·현재 모델의 도달 성능이 아닙니다. 이 통계가 현재 정확도 약 46%의 원인을 전부 설명하는 것도 아닙니다.

이 프로필을 정답 복사 규칙으로 사용하지 않고, 같은 프로필이 개발·검증 양쪽에 흩어지지 않도록 그룹으로 묶었습니다.

## 4. 공통 검증·학습 원칙

```text
train 6,201명
├─ 개발 4,960명
│  └─ 원본 프로필 그룹을 유지한 3-fold CV: 후보·변수·가중치 비교
└─ 홀드아웃 1,241명
   └─ 선택을 고정한 뒤 재평가; 이전에도 관측한 참고값

최종 유지/채택 설정
└─ train 전체로 최종 학습 또는 검증한 동일 설정의 완료 fit 재사용
   └─ test 2,546명 예측 → 피클·CSV 재현성 확인
```

- 개발/홀드아웃: `StratifiedGroupKFold(5, shuffle=True, random_state=42)`의 고정 분할.
- 개발 CV: 개발 환자에 그룹 3-fold, seed=43.
- v5·v6 재점검: 같은 개발 환자에 seed=57.
- v7 재점검: 같은 개발 환자에 seed=71. v8도 기준 통과 시 seed=71을 쓰도록 구현했지만 실제 v8 주 모델 후보는 1차 기준을 넘지 못해 실행하지 않았습니다.
- 그룹은 **원본 변이 문자열 전체가 같은 프로필** 기준입니다. 모든 전사체나 생물학적으로 동등한 변이를 완전히 묶었다는 뜻은 아닙니다.
- 사전·최소 빈도·지원도·선별 점수·상관·스케일러는 해당 학습 부분으로만 적합합니다.
- test는 기술통계·표기 점검·최종 추론에 사용했습니다. 학습 행, 사전 빈도, 증강 분포, 변수 선별, 모델 가중치 적합에 합치지 않았습니다.
- test의 암종 비율을 train과 같게 강제로 맞추지 않았고, test의 정답을 확인했다고 가정하지 않았습니다.

**중요한 한계:** 개발 CV와 홀드아웃은 여러 버전에서 반복 관측했습니다. 다른 seed도 같은 환자를 다시 나눈 것이므로 완전히 새로운 독립 시험이 아닙니다. 특히 v8 가이드가 전체 train 분석 자료라는 점은 특성 설계 단계의 선택 편향에 해당합니다. fold 안에서 통계를 다시 적합해도 이 설계 편향까지 사라지지는 않습니다.

### 4.1 스트레스 검증 정의가 버전 사이에 바뀌었습니다

| 버전 | 추가 조건 | 선택 기준 |
| --- | --- | --- |
| v2 | 학습 유전자 빈도에서 생성한 합성 배경 변이 | clean과 스트레스 F1 평균 |
| v4 | 합성 배경 변이 평균 10개/40개 | `0.5×clean + 0.25×stress10 + 0.25×stress40` |
| v5 이후 | 학습에서 2명 이하에게 관측된 실제 동의·치환 토큰을 평균 20개 추가; 같은 토큰을 중복한 조건도 비교 | `0.6×clean + 0.3×rare_noise + 0.1×duplicate` |

따라서 **v4 보고서의 스트레스 수치와 v5 이후 스트레스 수치를 그대로 이어 붙여 개선율을 계산하지 않습니다.** v5 이후의 v4 대조군은 새 조건에서 다시 평가한 값입니다. 합성 변이를 추가해도 정답이 유지된다는 가정은 생물학적으로 보장되지 않으며, 이 시험은 실제 test 분포를 재현한 것도 아닙니다.

### 4.2 채택 기준

v5는 기존 v4 대비 종합 점수 +0.002 이상, clean 하락 0.005 이하를 1차 기준으로 사용했습니다. v6 이후는 기준 모델 대비 종합 점수 +0.002 이상, clean 하락 0.002 이하를 요구했습니다. 통과 후보의 구성·가중치를 고정한 후 재분할에서는 종합 점수 기준 모델 이상, 정해진 clean 하락 허용 범위 안인지 확인했습니다.

이 기준은 운영상 정한 비교 규칙이며 통계적 유의성 검정이나 대회 점수 향상 보장이 아닙니다. 후속 결과가 작게 나왔다고 임계값을 낮춰 채택하지 않았습니다.

## 5. v1 — 다양한 변이 표현과 로지스틱·ExtraTrees 기준 모델

### 5.1 목적과 파생변수

원본 문자열을 바로 모델에 넣는 대신, 여러 관점의 숫자 단서로 표현하는 기본 모델을 만들었습니다. `IDH1=R132H`라면 유전자 존재, 정확한 토큰, 위치 132, 치환 유형 등의 단서를 동시에 만듭니다.

| 입력 계열 | 최종 개수 | 의미 |
| --- | ---: | --- |
| `gene` | 4,215 | 유전자별 변이 존재 |
| `variant` | 2,254 | 정확한 변이 표기 |
| `position` | 4,171 | 유전자별 단백질 위치 |
| `type` | 10,783 | 유전자별 변이 유형 |
| 환자 전체 숫자 요약 | 18 | 변이 유전자·토큰 수, 유형별 개수/비율, 복수 이벤트, 평균 위치 등 |
| 유전자 그룹 요약 | 7 | 명시한 경로 관련 유전자 목록의 변이 집계 |
| 합계 | 21,448 | 모델당 입력 수 |

범주형 변수는 학습에서 3명 이상 관측된 것을 남겼습니다. 개수에는 주로 log1p를 사용했고, 모든 행을 같은 크기로 맞추는 L2 행 정규화를 기본 모델에 적용한 것은 아닙니다.

### 5.2 학습 구성

| 모델 | 주요 설정 |
| --- | --- |
| 로지스틱 회귀 | `C=1`, 클래스 균형 가중치, `max_iter=2000` |
| ExtraTrees | 트리 300개, `min_samples_leaf=2`, `max_features=0.15`, 클래스 균형 가중치 |
| 앙상블 | 두 모델의 예측 확률을 50%씩 평균 |

학습 반복 한도와 실제 반복 횟수는 다릅니다. 저장 검증 기록의 최종 로지스틱 반복 횟수는 448회였으며, 최종 학습 수렴 경고는 0개였습니다. 모델 파일은 약 344MiB였습니다.

### 5.3 결과와 판단

- 개발 CV Macro F1: **0.418332**.
- 홀드아웃 Macro F1: **0.423701**, 정확도 **42.79%**.
- 사용자가 알려준 실제 Public: **0.2765425197**.

제출 CSV와 저장 예측의 일치·ID 정렬을 확인했고, 정렬 오류는 발견하지 못했습니다. 로컬 점수와 Public의 간격이 커서 입력 표기와 train/test 분포 차이를 추가로 점검했습니다. 학습·테스트를 분리했다는 사실만으로 일반화 성능이 보장되지는 않았습니다.

## 6. v2 — 표현·TF-IDF·배경 변이 증강 비교, 주 모델 미교체

### 6.1 목적과 변경

주석 방식 차이에 민감한 표현을 줄이고, 새로운 모델·정규화로 실제 차이에 견딜 수 있는지 살폈습니다.

| 실험 축 | 비교 내용 |

| 표기 정리 | 종결 X/별표, frameshift의 표기 차이 정리 |

### 6.2 결과와 판단

### 7.1 목적과 변경

```text
R213X → R213*
```

### 7.2 학습 가중치 재사용의 근거

- 실제 Public: **0.2765425197 → 0.2998780222**.
- Public 상승: **0.0233355025점**.

변경된 348개가 모두 추가 정답이라는 뜻은 아닙니다. 개별 정답은 모르지만, 사이트가 알려준 점수로 전체 개선을 확인했습니다. 모델 복잡도를 늘리기 전 입력 정합성 점검의 가치를 보여준 단계입니다.

## 8. v4 — 연관성·상관 중복 제거·변수 수·모델 규제 비교

### 8.1 목적

“변수를 전부 사용해서 오히려 성능이 떨어지는가?”라는 문제의식에서 출발했습니다. 입력 변수 수와 하이퍼파라미터는 구분했습니다. 변수는 모델이 받는 단서이고, 남길 변수 수·규제 강도·트리 깊이 등은 학습 설정입니다.

### 8.2 비교한 방법

| 실험 축 | 비교와 이유 |
| --- | --- |
| 타깃 연관성 | chi2, ANOVA F, L1 기반 내장 선별; 암종과 관련 있는 단서 우선 |
| 입력 중복 | 입력 변수끼리 절대 Pearson 상관 0.95/0.99 이상인 열의 중복 제거 |
| 입력 수 | 64/128/256/512에서 시작해 1,024/2,048까지 확대 |
| 요약 유지 여부 | 환자 전체 숫자 요약을 뺀 표현과 유지한 대조군 |
| 선형 모델 규제 | 로지스틱 C 변경 |
| 트리 복잡도 | LightGBM 잎 수, ExtraTrees 깊이 등 제한 |
| 서명 표현 | 암종별 서명 점수를 쓰는 후보도 비교했지만 최종 구성에 미포함 |

초기 80개에 추가 61개를 더한 **141개 단일 설정**을 같은 개발 그룹 3-fold에서 비교했습니다. 초기 결과를 보고 탐색 범위를 확장한 적응 탐색이므로 선택 편향이 있습니다.

암종에 붙인 숫자 코드와 유전자 값을 Pearson으로 상관 분석한 것이 아닙니다. 타깃은 다중 클래스 연관성 지표로, 입력 중복은 입력끼리의 상관으로 따로 다뤘습니다.

### 8.3 최종 구성과 설정

| 모델 | 선택 변수 | 선별/중복 기준 | 주요 학습 설정 |
| --- | ---: | --- | --- |
| 로지스틱 회귀 | 2,048 | chi2, 절대 상관 0.95 | C=0.1, 클래스 균형 가중치 |
| LightGBM | 2,048 | ANOVA F, 숫자 요약 유지, 0.95 | 트리 250개, 학습률 0.05, 잎 15, L2 규제 10 |
| ExtraTrees | 1,024 | ANOVA F, 숫자 요약 유지, 0.95 | 트리 250개, 깊이 20, 최소 leaf 3, max_features=sqrt |

세 모델이 선택된 실제 변이 특성을 직접 학습하고, 예측 확률을 같은 비중으로 평균합니다. 최종 모델은 L1 선별이나 서명 점수를 사용한 모델이 아닙니다.

### 8.4 변수 수와 성능 결과

| 항목 | v3 | v4 |
| --- | ---: | ---: |
| 선택 변수 합집합 | 21,448 | 2,063 |
| 분류기 입력 슬롯 합 | 42,896 | 5,120 |
| 모델 파일 | 약 344MiB | 약 40.28MiB |
| 개발 CV Macro F1 | 0.418332 | 0.413232 |
| 홀드아웃 Macro F1 | 0.423701 | 0.444544 |
| 홀드아웃 정확도 | 42.79% | 43.76% |
| Public | 0.2998780222 | 0.3169555443 |

2,063개는 **유전자 개수가 아니라 파생변수 합집합**입니다. 같은 변수를 여러 모델이 쓰므로 입력 슬롯 합과 합집합은 다릅니다. v3는 두 모델이 각각 21,448개를 받기 때문에 슬롯 합은 42,896개입니다. 선택되지 않은 원본 유전자도 전체 변이량 계산에는 기여할 수 있습니다.

선택 변수 합집합은 약 90.4% 줄었고, 실제 Public은 **0.0170775221점** 올랐습니다. 그러나 개발 CV와 v4 당시 스트레스 종합 점수는 낮았습니다. 변수 축소·규제·학습기가 함께 바뀌었으므로 상승 원인을 변수 수 하나로 단정하지 않았습니다.

### 8.5 클래스별 예: THYM

홀드아웃 THYM은 30명이었습니다. v3는 해당 클래스 F1이 0이었지만 v4는 30명을 모두 찾아 F1 약 0.4196을 기록했습니다. 다만 THYM이라고 예측한 수는 113명이어서 정밀도는 약 26.55%였습니다. **재현율이 높아져도 다른 암종을 잘못 끌어오는 문제는 남았습니다.** 이 결과는 정답을 아는 홀드아웃 사례이며 test 결과가 아닙니다.

## 9. v5 — 아미노산 변화·학습 지원도·직접 특성 학습·희귀 변이 증강

### 9.1 목적과 탐색 규모

v4 이후에는 입력을 무조건 더 줄이기보다, 표기 차이에 견디면서 유전자·변이 유형의 정보를 보존하는 표현을 비교했습니다. 초기 44개에 규제/지원도 12개, 증강 3개를 추가한 **총 59개 신규 설정**과 v4 고정 대조군을 평가했습니다.

### 9.2 전처리와 새 파생변수

| 변경 | 구현 의도 | 한계 |
| --- | --- | --- |
| 표기 정리 | 종결 X/별표, p. 접두사, `K16Rfs → K16fs` 통일 | 완전한 유전체·전사체 좌표 변환이 아님 |
| 동일 토큰 중복 제거 | 같은 셀에 같은 토큰이 반복돼도 한 번만 반영 | 서로 다른 변이를 같은 것으로 합치지 않음 |
| `aa` 변수 | `IDH1:R132H`와 함께 `IDH1:R>H` 추가 | 위치가 달라도 생물학적 효과가 같다는 뜻은 아님 |
| 지원도 가중치 | 학습에서 반복된 토큰/AA 변화와 낯선 변이를 다르게 반영 | 관측 빈도는 병원성의 증명이 아님 |
| 동의 변이 가중치 | 0/0.25/1 비교 | 동의 변이를 일괄 무해하다고 판정하지 않음 |
| 유전자별 요약 | 원시 변이 유전자 수, 가중 합, 비동의·stop/fs/del/ins 유형 요약, 유형별 비율 | in-frame del/ins를 기능 상실로 확정하지 않음 |
| 경로 그룹 | 기존 7개 목록의 가중 변이 합 log1p | 실제 경로 활성도 측정이 아님 |

지원도는 학습 환자 수 기준 2명/3명을 비교했고, 학습 행은 자기 출현 1을 제외했습니다. 일부 표현에서 낯선 치환은 0.25, 알려진 변이는 1, 같은 AA 변화가 지지되면 최대 0.75를 사용했습니다. 다른 표현은 낯선 변이·동의 변이를 그대로 1로 유지해 대조했습니다.

새 표현은 원시 변이 개수를 보존했습니다. 변이 블록만 TF-IDF/L2로 정규화하고 숫자 요약을 따로 보존한 후보도 비교했지만 최종 구성에 선택되지 않았습니다.

### 9.3 모델·규제·증강 비교

로지스틱, LightGBM, XGBoost, MLP, ExtraTrees를 비교했습니다. XGBoost·LightGBM도 선택된 **실제 변이 특성**을 직접 받습니다. 팀원 문서에 나온 “트리가 로지스틱 점수만 받았다”는 사례를 혜진 모델의 과거 구현으로 혼동하지 않았습니다. 점수 기반 stacking 자체도 올바른 OOF 구성이면 가능한 방법이지만, 이 최종 구성은 그런 방식이 아닙니다.

- 신규 LR: C=0.1/0.5, 블록 정규화 대조는 C=1/4.
- 신규 LightGBM: 트리 300개, 학습률 0.04, 잎 15, L2 규제 10.
- XGBoost: 트리 300개, 깊이 3/5, 학습률 0.04, L2 규제 10.
- MLP: 은닉층 128개, alpha=0.01/0.1/1/10 비교, 최대 250회, 클래스 균형 가중치.
- ExtraTrees 대조군도 포함했습니다.

MLP alpha=10은 성능이 크게 낮았고, 더 약한 규제도 일관되게 우수하지 않았습니다. 선택된 alpha=1 최종 모델의 실제 반복은 114회였습니다. 전체 후보 중 최대 반복에 도달한 경우가 있었으므로 모든 후보가 수렴했다고 말하지 않습니다.

증강 후보 3개는 학습에서 관측된 희귀 동의·치환 변이를 평균 10개 붙인 복사본을 추가했습니다. **원본 가중치 1, 복사본 0.5**이며 라벨은 같다고 가정했습니다. 사전·지원도·선별은 실제 원본 학습으로만 적합했고 증강 행이 원본 빈도를 늘리지 않게 했습니다.

두 로컬 분할에서 기준을 통과해 채택했습니다. 표현·지원도·학습기·증강·앙상블이 함께 바뀌었으므로 한 요소의 단독 효과라고 주장하지 않았습니다. test 라벨 변경은 v4 대비 512개였지만 정답 증가 수는 아닙니다. Public은 미확인입니다.

## 10. v6 — 암종별 선별·넓은 입력·특이도 가중치 비교

### 10.1 목적

팀원 사례를 참고하되, 실제 변이의 직접 트리 입력과 원시 변이량 보존은 v5에 이미 있다는 점을 확인했습니다. 남은 질문은 소수 암종의 단서가 전역 선별에서 밀리는지, 2,048개보다 넓은 트리가 도움이 되는지였습니다. 팀원 홀드아웃 0.4965는 분할이 달라 혜진 모델과 직접 우열 비교하지 않았습니다.

### 10.2 실험 구성: 초기 8개 + 추가 4개

| 축 | 비교 방법 |
| --- | --- |
| 전역 선별 | ANOVA 순위로 4,096개 입력 |
| 암종별 균형 선별 | 암종별 one-vs-rest 양성 방향 chi2 순위를 번갈아 채택 |
| 선형 모델 | 균형 선별 2,048개, C=0.1/0.5 |
| KL 특이도 가중치 | 학습 내 P(암종|변수)와 암종 비율의 KL 차이를 빈도/(빈도+20)으로 축소 |
| 부분 정규화 | 특이도 가중 변이 블록만 L2 정규화, 숫자/경로 요약은 별도 유지 |
| 추가 대조 | 넓은 입력과 희귀 변이 증강을 결합한 LGB 2개·XGB 깊이 3/5 |

KL 특이도는 통계적 연관성 이름이며 임상 specificity가 아닙니다. 신규 선별에서는 학습 값이 완전히 같은 열을 제거했고, 숫자·경로 요약을 보존했습니다. 기존 v5 구성의 Pearson 선별은 그대로 유지했습니다.

## 11. v7 — 복합 치환·동의/비동의 분리·변이량 보정, 미채택

### 11.1 목적과 파싱에서 발견한 것

v6가 놓친 표기와 낮은 변이량 환자의 오분류를 점검했습니다. 이전 분류기의 `other` 토큰은 train 173개, test 31개였습니다.

```text
483_484MP>IA → M483I + P484A
711_712FL>FL → F711F + L712L
M391        → 결과 아미노산이 없으므로 추측하지 않고 보존
```

시작·끝 위치와 양쪽 서열 길이가 모두 일치할 때만 분해했습니다. 분해 가능한 토큰은 train **176개**, test **29개**였고, 이 처리 후 `other`로 남는 것은 train 0개, test 2개였습니다. 176개와 이전 `other` 173개가 다른 이유는 일부 복합 표기가 이전 유형 판정에서 다른 유형으로 잡혔기 때문입니다. 예를 들어 연속 아미노산 `FS`는 frameshift 접미사 `fs`와 구분할 필요가 있습니다.

`other=0`은 현재 문법 분류를 마쳤다는 뜻이지 임상적 해석이 완성됐다는 뜻은 아닙니다. 위치를 임의로 ±3칸 같다고 처리하거나 모든 전사체 좌표를 정규화한 것도 아닙니다.

### 11.2 새로운 채널과 변이량 보정

| 방법 | 구현 |
| --- | --- |
| 결측/WT 구분 | missing 표시와 결측 수 log1p. 다만 train 결측이 0이라 효과를 입증하기 어려움 |
| `silent_gene` | 동의 변이가 관측된 유전자 |

## 12. v8 — 유전체 가이드·지문 점수·쌍별 전문가, 주 모델 미교체

### 12.1 가이드를 어떻게 사용했나요?

사용자가 제공한 `CANCER_GENOME_GUIDE.md`의 유전자·위치·동반 변이를 후보 설계에 참고했습니다. 문서 자체가 전체 train 분석 자료라서 설계 선택 편향이 있음을 기록했습니다. 문서의 주장 전체를 사실이나 모델 명령으로 받아들인 것은 아닙니다.

실제 train에서 재계산한 예는 다음과 같습니다.

| 표기 | 보유자 수 | 해당 암종 환자 수 | 보유자 중 해당 암종 비율 |
| --- | ---: | ---: | ---: |
| APC의 변이 표기 전체 | 367 | COAD 160 | 43.60% |
| APC stop/fs 표기 | 218 | COAD 155 | 71.10% |
| VHL의 변이 표기 전체 | 326 | KIRC 151 | 46.32% |
| IDH1의 변이 표기 전체 | 441 | LGG 180 | 40.82% |
| NPM1의 변이 표기 전체 | 56 | LAML 41 | 73.21% |

이 비율은 **P(암종|표기 보유)**이며 임상적 specificity `TN/(TN+FP)`와 다릅니다. “APC stop/fs면 95% 이상 COAD”라는 규칙을 넣지 않았습니다. test에 COAD가 570명 있다는 주장, 성별·흡연·CNV 증폭·바이러스 정보도 정답/입력으로 추정하지 않았습니다. 원본에 없는 증폭 정보를 단순 변이 표기에서 만들어내지 않았습니다.

### 12.2 가이드 기반 새 변수

| 계열 | 내용과 예 |
| --- | --- |
| `guide_gene` | APC/VHL/IDH1/BRAF/NPM1/TP53 등 문서 유전자에서 관측한 변이 |
| `guide_hot` | `IDH1:R132`, `BRAF:V600`, `SPOP:F133`, `KIT:D816`, `PIK3CA:H1047` 등 정확한 참조 아미노산·위치 |
| `guide_trunc` | stop/fs 표기. in-frame del/ins 전체를 절단으로 간주하지 않음 |
| `guide_pair` | APC+TP53, VHL+PBRM1, IDH1+ATRX, PTEN+CTNNB1, KRAS+SMAD4 등 동반 변이 |
| `guide_context` | 표지 존재 × log1p(전체 변이 유전자 수), 같은 표지의 변이량 맥락 표현 |
| `guide_observed_wt` | 한 유전자 변이와 다른 유전자의 관측 WT 조합; 결측을 WT로 보지 않음 |
| `guide_pattern` | 관측 변이 유전자가 TP53 하나뿐인 경우 등, 암종을 확정하지 않는 패턴 |

위치는 정확히 맞는지를 확인했고 `V6000`을 `V600`으로 오인하지 않도록 했습니다. 표지가 있다는 이유로 암종 정답을 덮어쓰지 않고, 모델이 가중치를 학습하게 했습니다.

### 12.3 학습 데이터에서 계산한 지문 점수

고정 가이드 외에 해당 학습 데이터에서 암종별로 자주 나타나는 유전자를 요약했습니다.

1. 유전자별 변이 유무에서 해당 암종/나머지의 양의 log-odds 차이를 계산.
2. 전체 최소 5명·해당 암종 최소 3명 관측 조건 적용.
3. 작은 표본의 영향을 줄이도록 `빈도/(빈도+20)`으로 축소.
4. 암종별 상위 8개 유전자 유지.
5. 26개 암종 각각에 점수 합·변이량당 점수·표지 일치 수를 만들어 최대 78개 요약 변수 생성.

라벨을 사용하는 통계이므로 **학습 입력은 내부 그룹 3-fold cross-fitting**으로 만들었습니다. 환자와 같은 원본 프로필 그룹을 제외한 내부 학습에서 계산한 통계로 그 환자의 학습 입력을 만들고, 증강 복사본도 같은 내부 통계로 변환했습니다. 외부 검증/test는 외부 학습 전체로 적합한 통계를 사용했습니다. 자기 라벨을 본 지문 점수를 그대로 자기 학습 입력에 넣지 않았습니다.

통계적 지문은 임상적 드라이버나 병원성 판정이 아닙니다.

### 12.4 초기 8개와 입력 보존 대조 4개

초기에는 가이드 전용 LR, 기존 변이 표현+가이드, 지문 점수 추가, 증강 LGB 등을 비교했습니다. 신규 변수를 2,048/4,096개 예산 안에서 우선 보존하면서 기존 변수가 밀려나는 영향을 확인할 필요가 있었습니다.

그래서 기존 v6 구성 모델의 **선택 변수 자체를 그대로 보존**하는 추가 대조 4개를 넣었습니다.

- 기존 raw LR의 chi2 기반 2,048개 + 가이드.
- 같은 LR 입력 + 가이드·지문 점수.
- 기존 넓은 증강 LGB의 4,096개 + 가이드.
- 같은 LGB 입력 + 가이드·지문 점수.

추가 변수 중 기준 입력과 학습 값이 완전히 같은 열은 제외했습니다. 이 대조는 입력 수가 조금 늘며, 예를 들어 LR은 약 2,193~2,275개, LGB는 약 4,291~4,374개 입력이 됐습니다. 초기 결과를 보고 4개를 추가한 적응 탐색이므로 편향이 있습니다.

### 12.6 헷갈리는 두 암종만 학습한 전문가

추가로 다음 4개 쌍에 대해 각각 클래스 균형 LR(C=0.1, 입력 1,024개)을 학습했습니다. 각 전문가의 사전·선별·학습은 해당 외부 학습 안의 두 암종 환자만 사용합니다.

| 쌍 | 비교 목적 |
| --- | --- |
| GBMLGG / LGG | 개발 OOF에서 많이 나타난 뇌종양 라벨 혼동 |
| KIPAN / KIRC | 개발 OOF에서 많이 나타난 신장 관련 라벨 혼동 |
| LUAD / LUSC | 가이드의 폐암 두 라벨 감별 아이디어 |
| THCA / SKCM | 같은 BRAF 표지라도 맥락이 다를 수 있다는 가이드 아이디어 |

원래 두 암종의 확률 합 M은 유지하고, 내부 비율만 전문가와 섞었습니다.

```text
M = 기존 P(A) + 기존 P(B)
기존 조건부 비율 = [P(A), P(B)] / M
새 조건부 비율 = (1-alpha) × 기존 조건부 비율 + alpha × 전문가 확률
새 [P(A), P(B)] = M × 새 조건부 비율
```

뇌/신장 2쌍만 또는 전체 4쌍을 사용하고 alpha=0.25/0.5를 비교했습니다. alpha=0.5는 **전체 앙상블을 50% 교체한다는 뜻이 아니라 두 암종 내부 비율의 혼합값**입니다. 다른 암종 확률은 유지합니다. 다만 최종 argmax가 달라지면서 다른 암종으로 예측이 바뀔 수는 있습니다.

- 기반: v6의 기존 8개 분류기 그대로.
- 추가: 뇌/신장 두 쌍의 LR 전문가 2개, 조건부 확률 비율 50% 혼합.
- 실제 분류기: 총 10개. 10개 확률을 단순 평균한 모델은 아님.
- 개발 clean F1: **0.436864**, v6보다 약 **0.001287** 높음.
- 스트레스 F1: **0.344399**, v6의 0.345775보다 낮음.
- 종합 점수: **0.408855**, v6보다 약 **0.000446** 높아 +0.002 기준 미달.
- 재분할·홀드아웃·Public 향상: **확인하지 않음**.
- test 예측 변경: v6 대비 **40개**. 추가 정답 40개라는 뜻이 아님.
- 제출 파일: [혜진_submission_v8_experimental.csv](../../submission/혜진_submission_v8_experimental.csv).
- 실험용 피클: `artifacts/v8/cancer_model_v8_experimental.pkl`, 약 83.20MiB.

독립 폴더에서 전체 2,546개의 CSV·ID·확률·배치 일치를 확인했습니다. 뇌·신장 쌍의 확률 합 보존과 나머지 암종 확률 유지도 검사했습니다. 자동으로 대회에 제출하지 않았으며, 사용자에게 실제 제출 결과가 공유되기 전까지 Public은 미확인입니다.

**배운 점:** 도메인 가이드는 후보를 만드는 데 유용하지만 확정 규칙은 아닙니다. 변수 우선 선별 때문에 기존 단서가 밀려날 수 있어 입력 보존 대조가 필요했고, 교차 적합을 지킨 지문 점수도 이번 실험에서 안정적인 이득을 보장하지 않았습니다. 작은 CV 상승과 주 모델 교체는 구분했습니다.

## 14. 실행·저장·재현성 관리

### 14.1 노트북 단독 실행

버전별 노트북에는 데이터 읽기, EDA, 파생변수, 학습 내 선별/통계, 검증, 모델 저장, 제출 CSV와 보고서 생성 코드가 들어 있습니다. 현재 주 노트북 `cencer.ipynb`는 v6입니다. 별도 프로젝트 Python 파일이 필수인 구조로 배포하지 않았습니다. 다만 원본 데이터와 해당 requirements 환경은 필요합니다.

### 14.2 캐시는 이미 끝낸 동일 계산을 재사용하기 위한 것

v7·v8에서는 원본 ID/프로필·클래스·분할을 확인하고 v6의 첫 fold를 실제 재학습해 완료 OOF와 일치하는지 확인한 후, 동일 분할의 나머지 v6 OOF를 재사용했습니다. 새 후보는 해당 학습에서 실제로 적합했습니다.

전체 train으로 학습한 모델 캐시는 후보를 고정한 뒤 전체 학습 단계에만 사용했습니다. **전체 train 모델을 CV·홀드아웃·재분할 예측에 사용하지 않았습니다.** 캐시 파일이 없거나 `CACHE_V6=False`이면 노트북에서 다시 학습합니다. 캐시 사용을 새 학습 결과나 새로운 독립 검증으로 표현하지 않았습니다.

### 14.3 피클·CSV 확인

- 학습된 전처리/모델과 추론 함수를 피클에 함께 저장.
- 프로젝트 Python 파일이 없는 임시 폴더에서 독립 로딩.
- 최신 결과에 대해 전체 test 2,546명의 확률·예측·CSV ID 일치 확인.
- 일부 행만 예측한 값과 전체 배치에서 같은 행의 값 비교.
- v8 실험용은 조건부 확률 재분배 제약도 확인.
- 실제 패키지·Python 버전과 파일 해시를 가능한 검증 기록에 저장.

배치 독립성은 한 환자의 결과가 같이 넣은 다른 환자 때문에 달라지지 않는다는 검사입니다. 모든 구성 모델의 중복 토큰 불변성이나 임상적 타당성을 보증하는 검사는 아닙니다. v5 이후에도 기존 v4 구성 일부가 남아 전체 앙상블이 완전히 중복 불변이라고 말하지 않았습니다.

| 같은 입력·다른 정답의 한계가 존재 | 원본 프로필 충돌 447그룹, 정답 복사 없이 그룹 검증 유지 |
| 좋은 한 번의 CV는 채택 근거로 부족 | v7은 재분할에서 미통과 |
| 약한 개선은 실험용으로 구분 | v8 전문가 모델은 별도 CSV이며 메인은 v6 |
| 실제 제출 점수와 로컬 성능을 분리해야 함 | 확인된 Public 개선은 v1→v3→v4, v5 이후 Public 미확인 |

다음 판단에서 우선 필요한 것은 **v5·v6 또는 v8 실험용의 실제 제출 피드백**입니다. 그 전에는 로컬 CV의 작은 변화가 test에서도 유효하다고 단정하지 않습니다. 새 실험은 고정 대조군과 같은 분할에서 비교하고, 어떤 구성·변수를 실제로 채택했는지와 어떤 검증을 아직 하지 않았는지를 계속 분리해 기록합니다.

## 17. 수치 출처와 갱신 규칙

- 실제 Public 3개: 혜진님이 대화에서 직접 제공한 값.
- v1: 초기 `verification.json`의 홀드아웃·모델 기록.
- v2: `artifacts/v2/configurations.json`, `model_comparison.csv`, `holdout_metrics.json`.
- v3: 전체 학습 특성 행렬 정합성 검증과 표기 수정 기록.
- v4~v6: 해당 버전의 설정, `selection.json`, `model_comparison.csv`, `confirmation_cv.csv`(해당 시), `verification.json`.
- v7: 위 검증 기록 외 `parser_audit.json`, `raw_profile_label_ambiguity.json`, 개발 오분류·변이량 진단.
